# Dependências distribuídas e código fonte

O shell Seraflix e sua UI são GPL-3.0. Não houve cópia de implementação dos wrappers Stremio com licença GPL-2.0 ou sem licença. Veja `estudo.md` para a análise anterior à implementação.

- **Node 22.22.2**: distribuição oficial darwin-arm64/darwin-x64, licença MIT e avisos de terceiros em `Node-MIT-e-terceiros.txt` dentro do app. Fonte: https://nodejs.org/dist/v22.22.2/node-v22.22.2.tar.gz . Os helpers não usam o runtime Intel do Stremio.
- **Sparkle 2.10.1**: licença MIT e avisos BSD/MIT de terceiros preservados em `Sparkle-2.10.1-LICENSE.txt` dentro do app. Código fonte: https://github.com/sparkle-project/Sparkle/tree/2.10.1 . O checksum do binary target é validado pelo Swift Package Manager.
- **FFmpeg 9.0.2 (helpers ffmpeg/ffprobe)**: compilado da fonte oficial https://ffmpeg.org/releases/ffmpeg-9.0.2.tar.xz , SHA-256 fixado em `dependency-lock.json`. Perfil padrão LGPL-2.1-or-later, sem `--enable-gpl`, `--enable-nonfree` nem bibliotecas externas opcionais; `ffmpeg-config.txt` e `FFmpeg-LGPL-2.1.txt` acompanham o app. Bibliotecas Apple são ligadas do sistema. Flags e receita em `build-ffmpeg.sh`; fonte correspondente é o tarball pinado e essa receita. Relink é possível recompilando o helper; não há DRM nem verificação de assinatura impedindo a substituição no app local.
- **libmpv e bibliotecas do player**: GPL-2.0-or-later/GPL-3.0 e licenças próprias de cada dependência conforme configuração. O perfil inclui suporte GPL e o conjunto do app é distribuído como GPL-3.0. O modo binário baixa 44 dylibs da distribuição oficial do IINA (https://iina.io/dylibs/universal/), sem copiar o app IINA, e confere SHA-256 para cada arquivo. O `dependency-lock.json` lista URLs, hashes, minOS das duas arquiteturas e dependências. libmpv inclui render API OpenGL e VideoToolbox. A lista contém componentes como libass (ISC), FreeType (FTL/GPL), HarfBuzz (MIT), libplacebo (LGPL), FFmpeg (LGPL/GPL conforme configuração), libarchive (BSD), libbluray/libudfread (LGPL), LuaJIT (MIT), MuJS (ISC), libdav1d (BSD), libjxl (BSD), LCMS (MIT), libvorbis/libogg (BSD), libwebp (BSD), zstd/lz4 (BSD), libsoxr (LGPL), rubberband (GPL), uchardet (MPL/GPL/LGPL). O arquivo de licenças e fontes produzido pelo modo source é a referência concreta da distribuição.

## Limite do snapshot binário de desenvolvimento

A distribuição pública de dylibs IINA não fornece uma associação verificável entre cada artefato publicado e seu commit de receita. O commit de referência `iina/deps-buildscripts@ee35579ded3ea95d839d85c2686d96dc505ee344` lista versões/fontes/patches e reproduz a arquitetura, mas não foi comprovado como fonte correspondente exata desse snapshot. Os hashes demonstram integridade dos arquivos consultados; não demonstram correspondência de fontes. Portanto o modo binário é usado para validação técnica inicial, e o workflow não publica uma release pública automaticamente a partir dele. A primeira versão deve registrar essa limitação junto dos artefatos de desenvolvimento.

Para uma release pública, use `DEPS_MODE=source`. A receita IINA e todas as fontes realmente utilizadas são arquivadas ao lado dos binários. Inclua fontes, avisos/licenças e receita de compilação na mesma release; revise também fontes de componentes GPL e dependências transitivas. Não rotule um pacote de desenvolvimento como release com conformidade de fontes comprovada.

## Streaming server

`server.js` não é distribuído no app. O artefato oficial contém indicação MIT, mas remete a `server.js.LICENSE.txt` indisponível no servidor no momento do estudo. O app baixa na primeira execução `https://dl.strem.io/server/v4.21.1/desktop/server.js`, valida SHA-256 `405eb494d6708406a30e716c3cfb5abae7a5e9c7a8b79446d64c3f821385930f` e guarda em Application Support. Atualizar versão/hash exige revisão e release nativa. Nenhuma licença de wrapper é usada como autorização implícita para redistribuir esse bundle.
